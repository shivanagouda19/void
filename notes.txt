#OOPS
    📘 Java OOP Quick Summary (Till Now)
    🔹 1. Class & Object
    Class → Blueprint/template
    Object → Instance of class (real entity)
    
    👉 Example:
    Class = Car 🚗 design
    Object = Actual car
    
    🔹 2. Attributes
    Variables inside a class
    Store data of objects
    
    👉 Also called: fields / properties
    
    🔹 3. Access Modifiers
    
    Control who can access data
    
    Modifier	Access
    public	Everywhere
    private	Only inside class
    protected	Package + subclass
    default	Same package
    
    👉 Used for security & data hiding
    
    🔹 4. Encapsulation
    Wrapping data + methods together
    Restrict direct access using private
    
    👉 Achieved using:
    
    Private variables
    Getter & Setter
    
    👉 Purpose:
    
    Data hiding
    Security
    Validation
    🔹 5. Constructors
    Special method used to initialize objects
    Same name as class
    No return type
    Types:
    Default constructor
    Parameterized constructor
    Copy constructor
    
    👉 Called automatically when object is created
    
    🔹 6. Destructor (Important Trick 🔥)
    ❌ Java does NOT have destructors
    ✅ Uses Garbage Collector
    
    👉 finalize() is deprecated
    
    🔹 7. Inheritance
    One class acquires properties of another
    
    👉 Keyword: extends
    
    Types:
    Single
    Multilevel
    Hierarchical
    ❌ Multiple (not supported with classes)
    
    👉 Promotes code reuse
    
    🔹 8. Hybrid Inheritance
    Combination of inheritance types
    
    👉 ❌ Not supported with classes
    👉 ✅ Achieved using interfaces

    Method Overloading (Compile-time Polymorphism)
    👉 Same method name, different parameters

    Method Overriding (Runtime Polymorphism)
    👉 Child class redefines parent method(both child and parent can have same method name)

    9 Abstraction-Hiding implementation details and showing only essential features
    Abstraction - idea not implementation


    🔹 3.          Encapsulation       vs      Abstraction (VERY IMPORTANT 🔥)
        Feature	    Encapsulation	            Abstraction
        Focus	    Data hiding	Hiding          implementation
        How	        private + getter/setter	    abstract class/interface
        Level	    Implementation level	    Design level
    
    ✅ Abstract Class
    👉 A class declared with abstract keyword

    🔹 Properties of Abstract Class
        Cannot create object ❌
        Can have:
            Abstract methods (no body)
            Normal methods (with body)
        Can have constructors ✅
        Must be inherited

    🔹 5. Can Normal Class Have Abstract Methods?
    👉 ❌ NO
